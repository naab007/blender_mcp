# v2.2.0

Phase B1 of the game-dev feature requests: armatures, skinning and weights, pose and
constraints, keyframes, playblast and bake, plus the rig-aware export. 169 tools (148 + 21; `tests/baseline_tools_2.2.txt` at the B1 test gate). Contract: docs/PLAN.md section 10 (K1-K23, C24+).

### Existing tools, rig-aware (B1-S L1/L1.1, add-on B1-A L1-L3.1)
- `export_object` gains `include_hierarchy` (the mesh exports with its armature, children
  and animation by default) and the FBX/glTF animation parameters (`bake_anim`,
  `add_leaf_bones`, `use_armature_deform_only`, `bake_anim_simplify_factor`,
  `mesh_smooth_type` validated against the live enum (`SMOOTH_GROUP` is 5.x only),
  `primary_bone_axis`, `secondary_bone_axis`, `apply_scale_options`, `export_animations`,
  `export_skins`, `export_morph`); parameters that do not apply to the chosen format are
  reported as ignored.
- `add_keyframe` keys pose bones (`bone`) and switches a quaternion bone to XYZ when an
  Euler path is keyed, reporting the switch.
- `capture_viewport_angle` / `capture_contact_sheet` gain `overlay`: `bones_in_front`,
  `wireframe`, `weight_paint`.
- `parent_object` gains `parent_type=BONE` with `bone`.
- `get_project_profile(apply_units=True)` re-applies the profile's engine units.
- `get_object_info` reports rig data (armature bones, pose position, action, bone
  collections; mesh vertex groups, shape keys, armature binding, parent type); `import_file`
  reports armatures, actions and `bone_shape_objects`, passes `disable_bone_shape=True` to the
  glTF importer so no Icosphere bone shape is left behind, and accepts `.bvh`.

- Rigging: Armatures & Bones: `create_armature`, `add_bones`, `get_armature_info`, `set_bone_properties`, `delete_bones`.
- Rigging: Skinning & Weights: `bind_armature`, `get_vertex_groups`, `get_vertex_weights`, `set_vertex_weights`, `render_weight_map`, `find_unweighted_vertices`.
- Rigging: Pose & Constraints: `set_pose`, `get_pose`, `reset_pose`, `add_constraint`, `get_constraints`, `remove_constraint`.
- Animation: `set_keyframes` (batch keys with interpolation and easing), `get_animation_info`,
  `playblast` (labelled frame grid, optional MP4), `bake_action` (constraints and IK into keys).
- Every act tool has a perceive twin; bones are returned by NAME; `set_pose` reports a
  rotation-mode switch; `find_unweighted_vertices(render=True)` returns the highlighted image

- Tier 2 (weights, shape keys, drivers, action management, NLA, mirror/rename, trajectory,
  apply-rest, Rigify) is staged and dry-run green on the server side but NOT in this release
  (Lead ruling: next run, needs the add-on handlers and a full test cycle).

### Fixes from the live pass on Blender 5.2.1 (A1.2, add-on f4dc37b1, shipped add-on now `0eb7ec4c` after A1.3; GUI-only, verified live by the live-test agent, not reproducible headless)
- F1 `capture_viewport_angle` wrote a 1x1 PNG on 5.2.1 (the DRAW_WIN_SWAP redraw inside the area/region override broke the following `screenshot_area`; redraw moved outside the override, 1x1 guard + retry; also fixed `capture_contact_sheet`, `render_weight_map`, `find_unweighted_vertices(render=True)` and the overlay captures).
- F2 `playblast(video_path=)` failed on odd dimensions ("height not divisible by 2"): dimensions are made even (tiles are always even-sized; an odd `max_size` rounds down by 1).
- F3 `playblast(camera=)` on the OpenGL path drew the viewport's own view: the region is switched to the camera view during capture and restored.
- F4 `start_blender(restore_session=)` reported "no window in this session" in a GUI session (`bpy.context.window` is None in the timer right after `open_mainfile`): `_gui_window()` falls back to the window manager's first window in `set_workspace` / `list_workspaces`.
- F5 `find_unweighted_vertices(render=True)` showed stale face selection: edge and polygon flags are cleared too.

### Follow-ups landed before the commit
- A1.3: `find_unweighted_vertices(render=True)` restores the mesh's vertex, edge and face
  selection afterwards.
- F6: the MCP server serialises commands to the add-on under a lock and resends a request
  once when the connection drops BEFORE the request reached Blender (never after), so a
  parallel batch of tool calls no longer loses one call to a reset socket.

### Blender 5.x facts users should know
- Actions are slotted on 5.x: `set_keyframes` and `add_keyframe` create the action's slot and
  bind it for you (`get_animation_info` reports it); on 4.x there are no slots. The action
  management tools (`create_action`, `assign_action`, ...) are Tier 2 and come with the next
  release.
- `playblast` needs a GUI session for the viewport path; headless it falls back to an EEVEE
  camera render (OpenGL rendering is refused in background mode on both versions). Video
  output needs `media_type` VIDEO on 5.x (mandatory in the GUI too; the add-on sets it).
- `set_workspace` replies with the previous workspace: Blender applies the switch on the next
  event-loop turn. `bake_action` names the baked action `Action`.
- Files saved by Blender 5.x do not open in 4.3.
