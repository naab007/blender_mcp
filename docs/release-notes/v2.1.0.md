# v2.1.0

Phase B0 of the game-dev feature requests: the whole file lifecycle, generic settings
access, presets, add-on and preference control, session state, and the server's own
settings file. 148 tools (92 in 2.0.0 + 56 new; the list is tests/baseline_tools_2.1.txt,
cut at the B0 test gate from server hash 598a765d). Wire protocol 1 (the first numbered one; any later wire change
bumps it).

**Install/upgrade:** as before. **The add-on and server must be updated together**: the
server now asks the add-on for `get_version` on connect and prefixes a one-time
`[blender-mcp mismatch]` notice to the next reply when versions or protocol differ; a
pre-2.1 add-on is detected from its "Unknown command type" answer.

### Add-on (B0-A L1, hash 39162cbf; L2, hash e0d7966c)
- The socket server starts automatically when Blender starts (preference "Start server
  automatically", default on; never in `--background`). The running state is runtime truth,
  no longer a Scene property saved into files.
- Port and the four API keys (Hyper3D, Sketchfab, Hunyuan3D id/key) moved from Scene
  properties into the add-on Preferences (password fields, `userpref.blend`). Keys found in
  a pre-2.1 `.blend` are migrated once on load and blanked in the file; the legacy Scene
  properties stay hidden through 2.2.0 and are removed in 2.3.0. Enter each key once per
  Blender installation.
- The server binds `127.0.0.1` and reports its bound port; new commands `get_version` and
  `ensure_server_running`; `bpy.app.handlers.exit_pre` closes the socket on 5.1+.
- `save_blend` gains `compress` (None = preference; on by default in 5.x), `relative_remap`,
  `copy`, `incremental` (Blender names `a.blend` -> `a1.blend`), `backup`, `overwrite`,
  `purge_orphans`; warns when saving a never-saved file; reply reports path, bytes,
  compression, dirty state, elapsed time and purged orphans.
- `load_blend` gains `force`, `save_first`, `load_ui`, `use_scripts`, `revert_on_fail` and a
  dirty guard (refuses to discard unsaved changes unless told); reply reports the previous
  file, the Blender version that saved the file and whether changes were discarded.
- `set_render_settings` gains 13 parameters (fps, fps_base, frame_start, frame_end,
  resolution_percentage, color_mode, color_depth, compression, denoise, device,
  use_persistent_data, use_simplify, simplify_subdivision), validated against RNA, with a
  set / unset reply like `add_modifier`.
- `get_scene_info` reports `file` state and a `settings_summary`.

### Server (B0-S L1 e0819668, L2 7a035061, L3 2123e09d, L4 598a765d = frozen)
- New settings file `~/.blender_mcp/settings.json` (or `BLENDER_MCP_SETTINGS_DIR`):
  host (default now `127.0.0.1`), port, connect_timeout, command_timeout, blender_exe,
  output_dir, presets_dir, image_max_pixels, log_level, img_to_3d_port. Precedence
  env > file > defaults. `get_server_settings` / `set_server_settings`.
- `get_version` tool: server and add-on versions, protocol match, module and settings
  paths.
- `start_blender` gains `start_server` (default True: the launch starts the add-on's socket
  server through a `--python-expr` hook, also headless) and `restore_session`; the timeout
  text names the two real causes. `get_blender_status` probes exactly like the connection.
- Command errors from the add-on raise `BlenderCommandError` and keep the socket; only
  transport failures reconnect.
- 56 new tools (file lifecycle, settings, typed conveniences, presets and profiles,
  add-ons / workspaces / preferences, session state) and six shipped presets; the full list
  is the five new category rows in README and TOOLS.md sections 27-31.
- (L4, 598a765d) `get_version` reports `Compatibility: unknown (add-on unreachable)` when
  Blender is not running instead of a false OK; `start_blender` auto-detection now reads the
  settings-file `blender_exe` between `BLENDER_EXE` and PATH; `output_dir` is the default for
  tools that leave files when their path is omitted (`render_all_cameras`, pathless
  `export_object`, `save_blend` / `save_copy` on a never-saved file, with a Note in the reply
  saying where the file went), never for image-returning tools; `restore_session_state`
  reopens the session's file and re-applies the state in one call (the add-on owns the
  dirty guard, the server only persists the JSON).

### Fixes
- `set_texture` no longer creates duplicate Normal Map and Displacement nodes on every
  call (the second linking pass is gone).
- PolyHaven HDR and EXR environments now share one colour-space try-list
  (`Linear Rec.709`, then `Linear`, then `Non-Color`); EXR no longer falls straight to
  Non-Color.
- Printed error strings are ASCII.
- `IMG_TO_3D_PORT` is honoured by the MCP server (env > settings file > 7862).

### Known facts
- On Blender 5.2 `bpy.data.is_dirty` is False at factory startup and, headless, stays False
  after edits; on 4.3 it is True from startup. Tools report it, never assume it; the
  `load_blend` dirty guard therefore fires headless only on 4.3. (Lead-verified 2026-09-11.)
