# v2.0.0

Blender 5.2 LTS is now the primary target. 92 tools, unchanged names and input schemas.
Headless harness on both installs: 134/134 on 4.3.2 and 134/134 on 5.2.1 (add-on git hash-object
`e0329ced83ca`).

**Install/upgrade:** download `addon.py` and install it via Blender > Preferences > Add-ons
> Install (or drop it over your existing copy and cycle the add-on off/on; the socket
server restarts automatically). On a fresh 5.2 install the user add-ons folder is
`%APPDATA%\Blender Foundation\Blender\5.2\scripts\addons\`. Update the MCP server with
`uv pip install -e .` from the repo. **The addon and server must be updated together**:
the `boolean_operation` solver value and the depth-map render path changed on the wire.

Blender 4.x support is best-effort from this release on: the code keeps 4.x paths behind
try-assign / hasattr guards, not version checks, but the test matrix runs on 5.2.1.
`bl_info["blender"]` minimum stays (4, 0, 0) (Lead ruling 2026-09-11).

### Breaking wire changes
- `boolean_operation`: `solver` accepts `EXACT`, `FLOAT` (`FAST` accepted as an alias and
  mapped to `FLOAT` on 5.x where the enum no longer has it) and `MANIFOLD` (Blender 5.2+,
  passed through only where the live enum has it). The error text lists the live enum.
  Enum evidence (Lead, 2026-09-11): 5.2.1 = FLOAT, EXACT, MANIFOLD; 4.3.2 = FAST, EXACT.
- `render_depth_map`: on 5.x the compositor tree is a temporary
  `CompositorNodeTree` node group assigned to the temp scene's `compositing_node_group`
  (Scene.node_tree is gone in 5.0); output is a `NodeGroupOutput` Image socket; nodes are
  resolved Compositor-id-first then Shader-id (`ShaderNodeMapRange`, whose output socket
  is `Result` on 5.x and `Value` on 4.3; both resolved). The Z pass is enabled on the
  view layer before the `Depth` socket is looked up.
- `set_render_settings` / engine fallbacks: `BLENDER_EEVEE` is resolved by assignment
  (`BLENDER_EEVEE` first, then `BLENDER_EEVEE_NEXT` for 4.x); no version branch.
- Image output: `ImageFormatSettings.media_type` (live enum on 5.2.1: IMAGE /
  MULTI_LAYER_IMAGE / VIDEO) is set per format before `file_format` (FFMPEG -> VIDEO,
  OPEN_EXR_MULTILAYER -> MULTI_LAYER_IMAGE, else IMAGE), guarded for 4.x; saved and
  restored by `_render_settings`. PNG stills were confirmed unaffected on 5.2.1 headless
  (media_type defaults to IMAGE); FFMPEG output is a live-session check.

### Addon
- The four 5.0 hard breaks fixed: EEVEE identifier, `Scene.node_tree` removal, boolean
  solver `FAST` -> `FLOAT`, `media_type` before `file_format`.
- `material.use_nodes` / `world.use_nodes` assignments are kept on purpose: removing
  them breaks 4.x (Lead ruling 2026-09-11); they are a no-op on 5.x and go with 6.0.

### Fixes
- `extrude_faces` no longer leaves the original face as an interior cap behind the
  extrusion.
- `subdivide_mesh`, `apply_modifier`, `export_object`, `set_origin` and
  `set_smooth_shading` restore the previously active object and selection.
- `set_texture` ARM maps failed on Blender 5.x: `ShaderNodeSeparateRGB` was removed in
  5.0, now resolved to `ShaderNodeSeparateColor` (PolyHaven textures with an `arm` map).
 
- PolyHaven HDRI downloads leaked their temp file (`tempfile._cleanup` does not exist on
  Blender's Python 3.11 / 3.13); the file is now removed after loading.
- `download_polyhaven_asset` (models, OBJ branch) called the removed
  `bpy.ops.import_scene.obj` unguarded (pre-existing, found by the migration grep); all
  three OBJ-import sites (`import_file`, PolyHaven, Hunyuan) now resolve the operator with
  `_op_exists`.
- `set_render_settings(file_format=)` accepts any Blender image format id plus the aliases
  `EXR`, `EXR_MULTILAYER`, `JPG`, `TIF`, `TGA`, case-insensitive.
- `set_render_settings` accepts bare `EEVEE` / `CYCLES` / `WORKBENCH` and lowercase;
  `boolean_operation` accepts lowercase and validates `operation` too.

### Server
- `boolean_operation` docstring and validation updated for `FLOAT`.
- `start_blender` auto-detection now finds portable zip installs (`D:\blender-<ver>-windows-x64`,
  the user's home and every fixed-drive root; highest version wins); `BLENDER_EXE` still
  overrides, and a path that does not exist is ignored.

### Known facts for users
- `.blend` files saved by 5.x open only in Blender 4.5 or newer (one-way). Keep 4.3.2
  for old projects; never re-save a 4.3 project from 5.2 without a copy.
- Blender 5.1+ bundles Python 3.13; the add-on's only third-party import (`requests`)
  is still bundled.
- GPU minimum for 5.x: NVIDIA Maxwell or newer, macOS 13+, no Intel Mac builds.
