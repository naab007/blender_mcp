# v2.4.0

Stage 1 of the game-dev feature requests: engine readiness (docs/FEATURE-REQUEST-engine-readiness.md,
categories 1-5: validation, optimisation and LODs, collision, sockets / pivots / hierarchy, engine export
presets). 22 new tools, all add-on handlers of the same name, plus additive parameters on six existing
tools. 204 tools (182 + 22; `tests/baseline_tools_2.4.txt` cut at the B2-G3 test gate), 192 add-on
handlers. Contract: docs/PLAN.md section 13 (B2.20, 24 amendments) and docs/LEAD-RULINGS-B2.md
(R-B2-1..42). Wire protocol stays 1: every 2.3.0 tool keeps its name, position and schema (additive
parameters only, with one relaxation: `apply_modifier.modifier_name` is optional).

### New tools (TOOLS.md sections 36-40)
- Validation (section 36): `validate_asset` (22 fixed check ids per mesh, PASS / WARN / FAIL with detail,
  count and sample indices; `fix=True` applies six safe fixes in a fixed order and re-checks; `fix=False` is
  read-only), `find_mesh_issues` (indices for one issue class, or a rendered view in a GUI session),
  `compare_meshes` (round-trip diff: counts, positions, vertex ORDER, custom normals, UVs, tangents,
  materials, groups; unrequested sections are omitted), `apply_transforms` (shared data isolated, negative
  scale reported, children keep their world transform), `fix_normals`, `cleanup_mesh`.
- Optimisation and LODs (section 37): `decimate_mesh` (by ratio or triangle target, at most 6 passes by
  `face_count` readback, optional copy), `generate_lods` (`<name>_LOD0..n`, names checked before any
  change), `set_normals` (`shade_smooth_by_angle` on both Blender versions; the 5.x Smooth by Angle modifier
  as an explicit option), `triangulate_for_export`, `get_triangle_budget`.
- Collision (section 38): `create_collision` (CONVEX / BOX / SPHERE / CAPSULE / CYLINDER / MESH_DECIMATED /
  SLICED_CONVEX, closed manifold hulls, engine naming `UCX_<mesh>_NN` / `-convcol` / `-col` / `_Collider` /
  `_COL`), `get_collision_info`, `check_collision_fit` (deterministic surface samples).
- Sockets, pivots and hierarchy (section 39): `add_socket` (`SOCKET_<name>` for Unreal, `#<name>` for
  Timbermesh with the `#` root rule), `list_sockets`, `set_pivot`, `snap_to_grid`, `build_export_hierarchy`
  (Unreal `lod_group` custom property, `UCX_` children, Godot `-col` siblings).
- Engine export (section 40): `get_export_preset` (the preset table, one source in the add-on),
  `export_for_engine` (validation gate: a FAIL verdict refuses the export unless `overrides` carries
  `force: true`; a temporary Triangulate modifier triangulates the file while the scene mesh keeps its
  polygons; `<file>.manifest.json` written by the add-on; textures copied / embedded / stripped / kept),
  `batch_export` (server loop, one file per object, per root or per collection, `batch_manifest.json`).
- Object names in list parameters: an exact name always wins (`Panel[1]` is addressable); globs apply only
  when nothing matches exactly. A name containing `,` cannot be addressed through a comma list: use
  `collection=` or the driver's `#uid`.

### Existing tools (additive)
- `export_object`: `objects` (comma list, alternative to `name`), `apply_modifiers`, `axis_forward`,
  `axis_up`, `global_scale`, `use_tspace`, `use_triangles`, `use_custom_props`, `colors_type`,
  `export_apply`, `export_tangents`, `export_extras`, `export_yup`, `export_attributes`,
  `export_vertex_color`, `export_animation_mode`; reply gains `size_bytes`, `object_count`,
  `vertices_written`, `triangles_written`, `warnings`, `transform_baked`, `modifiers_applied`.
- `import_file`: `axis_forward`, `axis_up`, `global_scale`, `use_custom_normals`, `use_image_search`,
  `ignore_leaf_bones`, `import_shading`, `merge_vertices`; reply gains per-object `objects` rows and
  `ignored` (kwargs the live importer lacks); `armatures` / `actions` / `bone_shape_objects` kept.
- `get_mesh_stats`: `triangles` is now the evaluated count (the 2.2.0 formula stays as `triangles_simple`);
  `ngons`, `quads`, `tris`, `loose_verts`, `loose_edges`, `non_manifold_edges`, `boundary_edges`,
  `has_custom_normals`, `uv_layers`, `color_attributes`, `material_slots`, `dimensions`,
  `unapplied_transform`, `origin_offset`. Pure read: never changes the mode or the active object.
- `get_scene_info(limit=None)`: `0` returns every object (the add-on default stays 10); entries carry
  `triangles`, `hidden`, `parent` and `collections`; `total_triangles` and `total_vertices`.
- `apply_modifier(apply_all=False, keep=None)`: `modifier_name` is optional with `apply_all`; reply
  `applied`, `kept`, `failed`, `remaining`.
- `set_origin`: `BOTTOM_CENTER`, `TOP_CENTER` and `CUSTOM` (+ `location`); reply `offset_applied`,
  `children_kept`, `isolated`; shape keys move with the mesh and a shared mesh gets its own copy first.
- `execute_blender_code`: the error block also prints the stdout captured before the exception.
- `get_version` (server text) prints the add-on's `registries` line.
- Server settings: `driver_batch_max` can only lower the add-on's limit of 200; a `driver_reply_max_chars`
  value of 0 or less falls back to 24000.
- The legacy Scene properties for API keys (`blendermcp_hyper3d_api_key`, `blendermcp_sketchfab_api_key`,
  `blendermcp_hunyuan3d_secret_id`, `blendermcp_hunyuan3d_secret_key`) are no longer registered. A file
  saved by 1.6.0-2.3.0 still migrates its values into the add-on preferences when opened, and the keys are
  deleted from every ID-property group that held them (a 5.x save keeps them in the system group).

### Driver interop and a 2.3.0 fix
- Every 2.4.0 tool is batchable and transactional through the generic driver (asserted by harness step
  B2-G8: a `batch` with `"$id.path"` references across `validate_asset` -> `decimate_mesh` ->
  `create_collision`, a `batch(undo=AUTO)` rollback of a B2 mutation, a `transaction` ROLLBACK over
  `set_pivot` + `add_socket`, `rna_get` on a `UCX_` proxy by `#uid`). `batch_export` is a server loop, so
  it is a tool call, never a batch item.
- 2.3.0 driver fix: `transaction` ROLLBACK (and `batch(undo=AUTO)`) now reverts Python-only mutations made
  after BEGIN, by pushing a closing undo step before the unwind; found by the 2.4.0 interop step. A
  ROLLBACK whose marker is already gone answers `{error: "transaction marker not found; nothing
  reverted"}`.

### Known Blender facts
- Blender's FBX exporter with `use_triangles` drops one face of Suzanne-like meshes (968 -> 967 triangles)
  in any round trip, regardless of doubles; a UV sphere round-trips exactly. The manifest keeps the
  evaluated count at export, so a manifest triangle count can read one higher than an engine import of
  such a mesh. Not add-on behaviour.
- An object in EDIT mode evaluates to 0 polygons in a `--background` session, so `get_mesh_stats.triangles`
  is 0 for it; the read tools flush the edit mesh first and take UVs from the BMesh.
- `shade_auto_smooth` is cancelled headless on 4.3.2 and adds a modifier on 5.2.1, hence `AUTO_SMOOTH`
  uses `shade_smooth_by_angle` on both; `calc_tangents` refuses ngons, hence the `ngons` check is FAIL for
  engines that export tangents; the Timbermesh plugin is present on the 4.3.2 install only.
- Data-block names are limited to 63 bytes on 4.3.2 and 255 on 5.2.1; the name checks use the live limit.

### Known limits
- Engine-readiness Tier 2 (`generate_lightmap_uv`, `remesh_object`, `reduce_bone_influences`,
  `check_vertex_count_split`, `make_single_user`, `merge_for_export`, `set_custom_properties` /
  `get_custom_properties`, `export_timbermesh`) is not in 2.4.0.
- Driver events (`events_subscribe` / `events_poll` / `events_unsubscribe`) are deferred to the
  generic-driver Tier 2 stage; the measured handler facts are in docs/PLAN.md 13.6.
- `vertex_count_16bit` counts vertices before export splitting; `flip_corrected` is populated on 5.2.1 only;
  `one_file_per=ROOT` and `OBJECT` differ only by `include_hierarchy`; Timbermesh export on 5.2.1 answers a
  teaching error until the plugin is installed there.
- Not verified headless: `find_mesh_issues(render=True)` images, `images_missing` with real image files,
  `bone_influences` on a real rig, a real engine import of the exported hierarchy, performance on large
  meshes (`validate_asset` is about six BMesh passes).
